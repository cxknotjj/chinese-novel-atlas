# Novel Atlas · 最终形态与功能文档

版本：0.2（读者向修订）  
日期：2026-11-28  
适用范围：产品定义、功能拆解、研发排期、对外介绍

---

## 1. 结论先行

Novel Atlas 的终局**不是一个更漂亮的地图生成器，也不是写作助手**，而是一个：

> **面向已完结网文读者的、证据可追溯的「世界档案发布器」。**

它把一本已经写完的小说编译成一份可查询、可对比、可发布的 `data.json`，再投影成两个产品面：

| 产品面 | 给谁 | 解决什么 |
|---|---|---|
| **发布面 · Atlas Reader** | 读者 / 同人 / 书评考据者 | 按自己的阅读进度查人物、地点、关系、伏笔和地图，不被剧透 |
| **Agent 接口 · Atlas Skills** | 读者 / 研究者 / 内容创作者 | 用自然语言查书、跨书对比、导出档案、生成地图 |

一句话概括产品目标：

> 让读者在读完第 N 章之后，能进入一个只属于前 N 章的世界：查得到、看得懂、不被剧透。

核心资产不是 21 件手绘 PNG，也不是八个视图，而是**数据契约 + 证据链 + 派生规则**。地图和视图是这套世界档案的表现层，不是产品的第一性。

---

## 2. 它现在是什么

当前项目已经具备一个很强的“分析内核”，但仍是一个**一次性拆书工具**：

- 输入 `.txt / .md`，按 10 章一批，由执行 agent 原生抽取，不调用外部 API。
- 产出 `data.json`（schema v2.0）和单文件 `atlas.html`。
- 八个视图：图谱、百科、地点志、地图、版图、节奏、境界、伏笔。
- 地图已升级为 21 件手绘 PNG + 9 件代码/SVG 变量层，由 `map_layout` 数据驱动。
- 一个 skill `novel-atlas`，内含六个流程：`analyze`、`ask`、`audit`、`compare`、`export`、`map`（装一次全有）。
- 59 个单元测试通过，CI 跑样例校验和构建。

真实数据也证明了它能承载完本长篇：

| 指标 | 《凡人修仙传》当前分析结果 |
|---|---|
| 原文规模 | 720.9 万字 / 2443 章 |
| 已分析 | 500 章（coverage 500/2443） |
| 实体 | 384 |
| 关系 | 459 |
| 伏笔 | 215 |
| 地点 | 119 |
| 设定概念 | 178 |
| 空间关系 | 20 |
| 地图节点 / 区域 | 39 / 3 |

这说明它不是玩具。但它现在的形态有一个结构性错位：

- **能力上是“世界模型”**：schema 里有境界、伏笔、认知隔离、空间证据、逐章摘要。
- **体验上还是“拆书报告”**：一次跑完，产出静态页面；没有阅读进度，没有按章截断，也没有面向读者的可查询入口。
- **视觉上更像“地图 demo”**：地图做得最好，默认页也是地图；但读者还需要人物、关系、设定、伏笔的统一入口。

所以最终形态要做的不是继续加视图，而是把“分析内核”升级成“面向读者的世界档案”。

## 3. 最终形态：一个发布面，一套 Agent 接口

### 3.1 形态

建议做成**本地优先的 Web 阅读器 / 静态站生成器**（桌面壳或本地 server 均可），复用现有 Python 核心和 `viewer` 前端，不锁定具体桌面框架。

```text
已完结小说文件
        │
        ▼
  ┌─────────────┐
  │  Atlas Core │  全书分章、批次抽取、合并、校验、版本化
  └──────┬──────┘
         │  data.json + anomalies.json + 版本快照
         ▼
  ┌──────────────────────────────────────┐
  │           Atlas Reader               │
  │  世界浏览 / 地图 / 搜索 / 阅读进度     │
  └──────────────────────────────────────┘
         │
         ├─ 单文件 atlas / 静态读者站 / 地图
         └─ agent skills（ask / compare / export / map）
```

### 3.2 两个产品面

**发布面 · Atlas Reader**

读者打开一本已完结小说，按自己的阅读进度进入世界：

- 世界浏览：图谱、百科、地点志、地图、版图、节奏、境界、伏笔。
- 阅读进度：默认只显示读到第 N 章为止的人物、地点、关系、事实和地图层。
- 全书搜索：人物、别名、地点、概念、伏笔关键词。
- 证据定位：每个结论都能回到 `chN:pM` 原文片段。
- 发布：单文件 HTML / 静态站 / 地图 PNG/SVG；可挂任意静态托管。

**Agent 接口 · Atlas Skills**

skill 不是产品本身，而是读者和内容创作者的对话入口：

- `analyze`：首次分析一本完本小说
- `ask`：带原文坐标的书内问答
- `compare`：跨书指标对比
- `export`：导出读者站 / 设定集 / 角色表 / 单文件
- `map`：地图审计、编排与渲染
- `audit`：疑点复核、误报标记（新增）

六个流程都在 `skills/novel-atlas/` 里；`SKILL.md` 只做路由，命令细节按需读 `references/<流程>.md`。

## 4. 目标用户与核心场景

| 用户 | 优先级 | 核心任务 | 最终产物 |
|---|---|---|---|
| 读者 | P0 | 查人、查设定、查伏笔、看关系与地图，且不被剧透 | 按进度截断的世界档案 |
| 同人 / 二创 | P1 | 快速查角色、地点、时间线，找可用的设定锚点 | 可检索的设定站 + 地图 |
| 书评 / 考据 / 研究者 | P1 | 找前后矛盾、伏笔回收率、节奏与设定密度 | 疑点索引 + 跨书对比 |
| Agent 用户 | P2 | 用自然语言完成上述任务 | skill 调用 + 证据化回答 |

核心 JTBD（Jobs To Be Done）：

1. “这个人是谁，第一次出现在哪一章？”
2. “他现在什么境界，什么时候突破的？”
3. “这个伏笔回收了吗，在哪一章？”
4. “A 和 B 到底是什么关系？”
5. “给我一张不剧透的世界地图 / 设定集。”

## 5. 功能模块

### 5.1 项目与输入（P0）

- 新建项目：书名、原著作者、题材、平台、完本状态。
- 导入：`.txt / .md` 优先；后续 `.docx / .epub`、飞书文档。
- 全书分章：沿用 `chunk.py` 的模式探测、编码探测、字数兜底。
- 章节索引：每章显示“未分析 / 已分析 / 失败 / 跳过”，支持断点续跑和补跑。
- 覆盖率：明确展示 `chapters_done / chapters_total`；发布和跨书对比要求 100% 覆盖。
- 源文件快照：记录文件 hash 与版次，避免“分析了错版/删改版”。
- 完本优先：不设计连载更新流；同一本书换版或修正数据时重跑，保留版本快照即可。

### 5.2 世界模型（P0）

`data.json` 仍是唯一事实源，不引入第二套数据库。最终应增加三层能力：

1. **稳定 ID**：同一本书重跑、换版时，实体/地点/伏笔 ID 不漂移。
2. **版本快照**：每次分析生成 `snapshots/YYYYMMDD.json` 或 `versions/vN.json`，支持 `diff`。
3. **as-of 查询**：`worldStateAt(ch)` 返回“第 N 章时读者/角色分别知道什么”，供阅读进度截断、剧情感知和认知检查使用。

现有表全部保留：

- `entities / relations / realms / power_history`
- `chapters / battles`
- `foreshadows / knowledge`
- `places / spatial_relations / map_layout`
- `concepts / volumes`

### 5.3 一致性引擎（P0，档案可信度）

当前只有伏笔状态是真正“派生”的；战力、认知、死亡、时间线还只是数据，不是规则。最终需要独立的 `anomalies.json` 和规则引擎。

读者需要的不是“作者改稿”，而是“这本完结书的设定有没有互相矛盾、疑点在哪、原文证据是什么”。

**疑点对象**

```json
{
  "id": "an_fs_001",
  "kind": "foreshadow_unresolved",
  "severity": "info",
  "confidence": "high",
  "title": "抽髓丸：第 20 章埋下，第 73 章后未再提",
  "chapter_range": [20, 500],
  "entities": ["f_chousuiwan"],
  "evidence": [
    {"coordinate": "ch20:p8", "quote": "……"},
    {"coordinate": "ch73:p4", "quote": "……"}
  ],
  "detail": "沉默 427 章，超过当前阈值 75 章",
  "reader_note": "可能是作者有意留白，也可能是未回收支线；读者自行判断",
  "verified": false
}
```

**规则清单**

| 规则 | 输入 | 输出 |
|---|---|---|
| 伏笔未回收 | `foreshadows` + `mentions` | 埋设/回收/沉默时长 |
| 战力倒退 | `power_history` | 境界 order 下降 |
| 越级战斗 | `battles.gap` + 前置章节 | 越级战斗候选 |
| 认知穿帮 | `knowledge.known_by` + 对话/章节 | 角色提前知道 |
| 死亡再出场 | `entities.status` + `chapters` | 死亡后出场 |
| 时间线冲突 | 章节内时间词 + `first_ch` | 先后矛盾 |
| 物品断线 | 器物首次出现/最后一次出现 | 凭空消失/凭空出现 |
| 地点冲突 | `spatial_relations` + `map_layout` | 方位/包含矛盾 |
| 关系突变 | `relations` 时间线 | 无事件支撑的同盟/敌对翻转 |
| 别名候选 | `entities.aliases` + 上下文 | 疑似同一人 |

**原则**

- 只产出“疑点”，不给改稿建议，不自动改稿。
- 每条疑点必须有 `chN:pM` 证据；没有证据不进入索引。
- 疑点保留 `confidence` 和 `reader_note`，避免把作者留白误判成错误。
- 完本分析可以全量重跑；不设计作者侧的“问题收件箱/已修/误报”工作流。

### 5.4 阅读进度与剧透控制（P0）

这是读者向产品和作者向工具最大的区别。

- 阅读进度 `cutoff_ch`：默认全书，读者可拖到“我刚读到第 N 章”。
- 所有视图只显示 `first_ch <= cutoff_ch` 的实体/地点/关系，以及 `truth_ch/reader_known_ch <= cutoff_ch` 的事实。
- 地图只显示该进度前已经出现的区域、节点、路线；未来层不画。
- 伏笔只显示已埋下的，不显示埋设章之后的回收信息。
- 境界只显示截至该章的战力节点。
- 搜索命中未来内容时，显示“该结果在第 N 章后出现”，默认不展开。

有了这一层，同一份 `data.json` 可以服务“刚读到 100 章”和“已经读完”的两类读者，而不需要维护两套数据。

### 5.5 世界浏览（P1）

- 保留八视图和跨视图跳转。
- 图谱：核心/全部范围、势力过滤、关系类型过滤。
- 百科：人物/势力/地点/概念分页 + 别名搜索。
- 地点志：L1–L4 地理层级（大陆 / 海洋 / 界面三分支）、首现章、证据、所属势力。
- 版图：势力 × 据点矩阵、同盟/敌对、未归属缺口。
- 节奏：钩子率、爽点间隔、平均章字数、平台基准；不完整分析时标注“不可比”。
- 境界：多色相战力时间线；每个境界独立色相，同境界内由浅到深，突破到下一境界后换色并重新从浅色开始；突破章、越级战斗标记。
- 伏笔：埋设/回收章、未回收/仅提及区分、沉默时长。
- 所有视图受阅读进度 `cutoff_ch` 约束：不显示读者尚未读到的实体、关系和地图层。

### 5.6 地图（P1，视觉差异化）

地图在产品里是“世界浏览”的一等视图，但不是唯一入口。最终要做三件事：

1. **M0–M4 成熟度自动分级**
   - M0 地点索引：没有坐标，只列表。
   - M1 拓扑/示意：`places.parent` + 传送/航线；示意 2D 可按包含关系随机/自动摆放，不表达证据方位。
   - M2 证据方位：只消费带原文证据的 `direction/distance/contain/adjacent`，不足 3 条自动回退 M1。
   - M3 多层地图：位面/上下界/星域/楼层，父地图下钻。
   - M4 时态地图：按章节切片，国界/控制权/路线随章节变化。

2. **地图编排器**
   - 制作者/分析者不写 JSON 也能拖拽节点、选 stamp、调层。
   - 复用 `atlas-kit` 的 21 件 PNG + 9 件代码组件。
   - 支持“底件库 + 风格包 + 世界包”三件套，多本书共用。

3. **发布地图**
   - 分析版：显示证据徽标、M 等级、免责声明。
   - 读者版：去掉分析侧标注，按阅读进度截断。
   - 导出 PNG / SVG / 静态页。

**边界**：示意坐标不是经纬度；示意 2D 只保证包含关系，原文没写方位时可随机摆放并避开建筑；纸面上的山、海、建筑是视觉底件，不是原文地理。地图不显示比例尺/经纬网，罗盘只作装饰。

### 5.7 发布面（P1）

**读者站**：

- 按 `cutoff_ch` 截断：角色、地点、势力、地图层、关系只显示到该章。
- 读者认知：只显示 `reader_known_ch <= cutoff_ch` 的事实。
- 隐藏 `foreshadows`、`power_history` 未来节点、未公开区域。
- 可导出静态站，挂 GitHub Pages / 任意静态托管。

**地图发布**：单图 / 多图层 / 章节切片。

**设定集导出**：单文件 HTML / Markdown / 角色表 / 地点表。  
不提供作者报告、改稿清单或编辑审稿产物。

### 5.8 Skills（P1）

| 流程（同属 `novel-atlas`） | 状态 | 最终职责 |
|---|---|---|
| `analyze` | 已有 | 首次分析完本、批次抽取、合并 |
| `ask` | 已有 | 结构查询 + 原文定位 |
| `compare` | 已有 | 跨书指标对比 |
| `export` | 已有 | 读者站 / 设定集 / 角色表 / 单文件 |
| `map` | 已有 | 地图编排、审计、构建 |
| `audit` | 新增 | 疑点复核、误报标记、考据索引 |

最终 skill 的入口应该统一到“项目”而不是“文件”：

```text
分析《凡人修仙传》完本
韩立第几章筑基？
对比两本书的伏笔回收率
导出到 500 章的读者版
```

## 7. 版本路线

### V1 · 读者版世界档案（下一步重点）

只做四件事，不继续加视图：

1. 完本分析 + 作品概览（人物/地点/关系/地图入口）。
2. `anomalies.json` 疑点索引 + 原文证据。
3. 阅读进度 / 剧透截断（`cutoff_ch`）。
4. 静态读者站 / 单文件导出。

验收：读者读完第 N 章后打开档案，只看到前 N 章的人物、地点、关系和地图，不出现后续剧情；每条疑点都能回到原文。

### V2 · 世界模型与考据

1. 认知穿帮、死亡再出场、时间线、物品断线规则。
2. 别名归一助手（当前最大技术风险）。
3. 地图 M3/M4 + 地图编排器。
4. 版本快照与重跑对比。

### V3 · 发布与多书

1. 读者站发布 / 阅读进度记忆。
2. 多书库与跨书对比 UI。
3. 分享 / 静态托管。
4. 可选公开 API（只读）。

## 8. 验收标准

**数据**

- 发布和跨书对比要求 `coverage.chapters_done == meta.chapters`。
- 每条疑点必须有 `chN:pM` 证据；无证据不进入索引。
- 同一本书重跑/换版后实体、地点、伏笔 ID 不漂移。

**疑点**

- 疑点有 `confidence` 与 `reader_note`，不把作者留白误判成错误。
- 不输出改稿建议；只给原文证据和可能解释。
- 同一疑点不重复刷屏。

**地图**

- 每个层显示 M0–M4 等级。
- M2 只在方向/距离约束 ≥3 条时开放，否则回退 M1。
- M3/M4 有数据才显示，不硬造 z 轴和时间切片。
- 示意坐标不写回 `places`，不显示比例尺/经纬网。

**发布**

- 读者版可按章节截断，未来事实不可见。
- 分析侧数据（未来战力、未公开地图层）默认不发布。

**质量**

- CI 继续跑 59+ 测试；新增黄金语料回归。
- 不引入外部 API、key、云端书库。
- 样例单文件 < 3 MB；500 章页面保持 2–3 MB 量级。

## 9. 不做什么

- **不写小说、不续写、不改文风**。只做世界档案和疑点索引。
- **不做作者工作台**。不做连载更新提醒、改稿清单、编辑审稿流。
- **不做通用 RAG 聊天**。先查结构，再回原文，答案必须带坐标。
- **不做精确 GIS**。示意地图不承担经纬度、比例尺、真实海岸线。
- **不做 SaaS 书库**。默认本地，稿件不上传、不训练。
- **不做“更多 tabs”**。八视图已经够多，下一步是收口成读者档案。

## 10. 一句话记住

# atlas-compare · 跨书对比

把多个 `data.json` 放在一起，产出可比指标和并排视图。对比是**读者/研究者视角**，不是“作者和爆款差在哪”的改稿诊断。

## 前置

至少两本已拆解的书：

```bash
ls output/*/data.json
```

**schema 版本必须一致。** 版本不同先转换。

**覆盖口径**：发布和正式对比要求 `coverage.chapters_done == meta.chapters`。只分析了前 N 章时，`metrics.md` / `compare.html` 必须标注“抽样数据，只能看趋势”；不要拿 20% 覆盖率和 100% 覆盖率比回收率。

## 网文的可比指标

| 指标 | 计算方式 | 说明什么 |
|---|---|---|
| **伏笔回收率** | `payoff_ch` 非空的条数 / 总数 | **最关键的指标**，低于 40% 说明坑太多 |
| **伏笔超期率** | 超期条数 / 总数 | 超期 = 超过 `max(50, 章数×0.15)` 未收 |
| **钩子率** | `hook` 非空章数 / 总章数 | 番茄 ≥80%，起点 ≥60% |
| **爽点间隔** | 相邻 `emotion=爽` 章号差的中位数 | 番茄 3 章，起点 10 章 |
| 平均章字数 | `words` 均值 | 番茄 4000，起点 6000 |
| 平均章节张力 | `tension` 均值 | 整体强度 |
| 境界层数 | `realms.length` | 战力天花板的高度 |
| 升级速度 | 主角升一级的平均章距 | 太快没张力，太慢读者跑 |
| 人物数 / 关系数 | 计数 | 世界规模 |
| 关系密度 | 关系数 / 人物数 | >3 高度交织，<1.5 结构松散 |
| 势力数 | `group` 去重 | 阵营复杂度 |
| 设定密度 | (`places` + `concepts`) / 万字 | 世界观厚度 |

**这些指标只在 schema 一致时可比。** 这就是为什么关系类型必须收敛到 8 类——否则连"冲突线占比"都算不出来。

## 执行

```bash
python "<SKILL_DIR>/scripts/compare.py" \
  --a output/{书名A}/data.json \
  --b output/{书名B}/data.json \
  --out output/_compare/
```

> 脚本会校验两本 `schema_version` 一致（只支持 2.0）；任一本未覆盖全书时，`metrics.md` 会追加"抽样数据，只能看趋势"的警告。

产出：

```
output/_compare/
  metrics.md          指标对照表
  compare.html        并排视图（两个图谱 + 指标条）
  diff.json           差异明细
```

## 硬性约束

1. **不要跨 schema 版本硬比。** 字段含义变了，比出来的数字是错的。
2. **不要在样本量不足时下结论。** 只对比 2 本书时说"这个题材就是这样"是过度归纳。
3. **指标要给绝对值和相对值。** 只看百分比会误导（分母不同）。
4. **伏笔指标必须标明阈值。** "超期 7 条"要知道是按 `max(50, 章数×0.15)` 算的。
5. **抽样数据不能直接比。** 如果某本只有部分章节摘要（`chapters.length < coverage.chapters_done`），节奏指标要标注"不完整"。

## 已知限制

- 关系类型靠模型判定，跨书可能有标注漂移（同一段关系在一本标 `social`，另一本标 `alliance`）
- `group` 的划分标准各书不同，势力数只能同书系内比
- 当前只支持 2 本并排，3 本以上是表格不是图
- 境界层数不可直接跨题材比（都市文可能只有 2 级，玄幻有 9 级）

# atlas-ask · 书内问答

基于 `atlas-analyze` 产出的 `data.json` 回答问题。

## 前置

必须已经有 `output/{书名}/data.json`。没有就先跑 `atlas-analyze`。

```bash
ls output/*/data.json
```

## 回答顺序（重要）

**先查结构，再回原文。不要一上来就 RAG 检索。**

### 1. 实体匹配

用户提到的人名，先过三张表：

1. `entities[].name` 精确匹配
2. `entities[].aliases[]` 别名匹配（"凤姐" → 王熙凤）
3. `concepts[]` / `places[]` 名称匹配

命中则直接拿到该实体的 `desc`、`attrs`、`first_ch`。

### 2. 关系查询

问"A 和 B 什么关系"时：

- 查 `relations` 里 `(s,t)` 或 `(t,s)` 的所有边
- 可能有多条（既是表亲又是诗社社友），**全部列出，标注类型**
- 附带 `label` 和 `first_ch`（"第 3 回确立"）

### 3. 出场定位

问"XX 在哪出现"时：

- 优先用 `events[].entities` 反查
- 再用 `relations[].first_ch` 补充
- 输出章号列表，**不要编造段落坐标**

### 4. 结构化查不到才回原文

```bash
python scripts/seek.py --dir output/{书名}/ --keyword "护官符" --context 2
```

只返回命中位置前后 2 段，**不要整章加载**。

## 输出格式

```
【王熙凤】

贾琏之妻，王夫人内侄女。手段泼辣，协理宁国府、弄权铁槛寺，最终机关算尽。
身份：贾琏妻 · 结局：病亡，家败人散 · 首次登场：第 2 回

关系（9 条）
· 贾琏 — 夫妻 · 第 2 回
· 平儿 — 主仆兼通房 · 第 6 回
· 贾母 — 祖孙 · 第 3 回
…

出处：data.json · 依据 ch03:p04、ch06:p12
```

## 硬性约束

1. **答案必须能追溯到 `data.json` 的字段，或原文的具体坐标。** 两者都没有，就说"数据里没有"。
2. **不要用模型常识补充。** 用户问的是"这本书里怎么写"，不是"红楼梦讲什么"。
3. **不确定时给候选。** 如果匹配到多个实体（"三姑娘"可能指探春也可能指别人），列出来让用户选。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 直接凭记忆回答红楼梦的问题 | 先查 data.json，查不到就说没有 |
| 把"木石前盟"当成关系类型 | 它是 `label`，`type` 是 `romance` |
| 回答"黛玉死于第 98 回"却无出处 | 引用 `events` 或原文坐标 |

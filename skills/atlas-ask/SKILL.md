# atlas-ask · 书内问答

基于 `atlas-analyze` 产出的 `data.json` 回答问题。

## 前置

必须已经有 `output/{书名}/data.json`。没有就先跑 `atlas-analyze`。

```bash
ls output/*/data.json
```

## 回答顺序（重要）

**先查结构，再回原文。不要一上来就 RAG 检索。**

### 1. 实体匹配

用户提的名字，先过三张表：

1. `entities[].name` 精确匹配
2. `entities[].aliases[]` 别名匹配（网文的称号极多："剑尊""魔帝""老祖"）
3. `places[]` / `concepts[]` 名称匹配

命中则拿到 `desc`、`attrs`、`first_ch`、`power_history`。

### 2. 境界查询

问"XX 现在什么境界"时：

- 取 `power_history` 里 `ch <= 当前章` 的最后一条
- 输出"第 N 章 · 金丹中期"，**不要只给一个境界名**
- 如果用户问"什么时候突破的"，列出整条时间线

### 3. 伏笔查询

问"那个玉佩收了没"时：

- 在 `foreshadows[].content` 里做关键词匹配
- 输出：埋设章、回收章、状态（**用 `status` 派生规则现算，不信任存储值**）
- 超期的要明确说"已超过阈值 N 章"

### 4. 关系查询

问"A 和 B 什么关系"时：

- 查 `relations` 里 `(s,t)` 或 `(t,s)` 的所有边
- 可能有多条（既是师徒又是仇敌），**全部列出，标注类型和起始章**

### 5. 结构化查不到才回原文

```bash
python scripts/seek.py --dir output/{书名}/ --keyword "云纹玉佩" --context 2
```

只返回命中位置前后各 2 段，附带 `chN:pM` 坐标，**不要整章加载**。可加 `--chapter-range 1-200` 限定范围，`--json` 供程序消费。

## 硬性约束

1. **答案必须能追溯到 `data.json` 的字段，或原文的具体坐标。** 两者都没有，就说"数据里没有"。
2. **不要用模型常识补充。** 用户问的是"这本书里怎么写"，不是"网文一般怎么设定"。
3. **境界一定要带章号。** 只回答"金丹期"是错的——200 万字的书里，角色会升好几级。
4. **不确定时给候选。** 匹配到多个实体就列出来让用户选。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 直接凭记忆编造角色境界 | 先查 `power_history`，查不到就说没有 |
| 把"一饭之恩"当成关系类型 | 它是 `label`，`type` 是 `alliance` |
| 回答"第 98 章结丹"却无出处 | 引用 `chapters` 或原文坐标 |
| 伏笔状态照抄 `status` 字段 | 用 plant_ch / payoff_ch / 阈值现算 |
